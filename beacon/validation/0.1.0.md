# Beacon Python 0.1.0 正式版验收记录

## 结论

`beacon-otel==0.1.0` 与 `beacon-profiling==0.1.0` 以 `0.1.0rc2` 已通过的功能与接收端验收为基线。正式版发布前重新执行版本一致性、代码格式、制品构建、制品元数据、安装后测试及 Python 3.10–3.14 CI；发布后从公开 PyPI 进行干净安装和启动验证。

## 功能基线

- OpenTelemetry Python Contrib：`v0.65b0`
- OpenTelemetry Python Core：`v1.44.0`
- Python 支持范围：3.10–3.14
- Trace：标准 OpenTelemetry 自动插桩及 OTLP 导出
- Profile：CPU Time、Wall Time、Heap Live Size、锁竞争与已处理异常采集
- Profile 默认导出周期：60 秒，可通过环境变量或构造参数修改

DataKit Trace 与兼容 pprof 接收、Profile 数值语义、默认导出周期、FastAPI Demo 和 Trace/Profile 关联已在 `0.1.0rc2` 完成验收；证据见 [`0.1.0rc2.md`](0.1.0rc2.md)。正式版相对该候选版不引入运行时功能变化。

## 正式制品检查

发布前必须通过：

- `python beacon/scripts/check-version.py --tag beacon-v0.1.0`
- 两个 wheel 与 sdist 构建及 `twine check`
- wheel 名称、版本和固定 OpenTelemetry 依赖检查
- 从构建 wheel 安装后执行 Beacon 自有测试
- `beacon --version` 输出 `Beacon Python 0.1.0`
- Python 3.10、3.11、3.12、3.13、3.14 CI

发布后必须核对：

- PyPI 同时存在 `beacon-otel==0.1.0` 与 `beacon-profiling==0.1.0`
- GitHub Release `beacon-v0.1.0` 为正式版本并包含两个包的 wheel 与 sdist
- 全新虚拟环境可从公开 PyPI 安装 `beacon-otel[profiling,requests]==0.1.0`

## 已知限制

- 当前 DataKit 接收路径使用兼容 pprof，而不是 OTLP Profiles v1development。
- `tracemalloc` 在大量小对象和很短的内存快照周期下开销明显；默认周期为 60 秒，可通过环境变量或构造参数调整。
- OpenTelemetry Resource 属性进入 DataKit 后会按 DataKit Trace 字段模型归一化，非内置标签可能保留在扩展属性中。
- 不要在同一 Python 环境中混装旧版 `guance-sdk-extension-profiling`，其自动插桩入口会与 `beacon-profiling` 冲突。
